By the end of this lesson you will be able to spot a repeating group in a table and fix it so each cell holds one value.

First Normal Form (1NF) is a fundamental concept in database normalization. It defines the basic requirements for organizing data in a relational database.

In First Normal Form, a table is structured in a way that eliminates repeating groups and ensures that each column contains only atomic values. This means that each cell in the table must hold a single value, and there should be no multiple values or sets of values within a single cell.

To meet the requirements of 1NF, tables should have:

1. A unique name for each column.
2. Atomic values in each cell, meaning that each value should be indivisible.
3. A unique identifier, such as a primary key, to identify each row uniquely.

By organizing data in 1NF, we eliminate data duplication and redundancy, making it easier to manage and update the information. It allows for efficient querying and ensures data integrity.

It's important to note that achieving 1NF is the foundation for higher levels of normalization, such as Second Normal Form (2NF) and Third Normal Form (3NF). These subsequent normal forms build upon the principles of 1NF to further improve data organization and minimize data redundancy.

## Example

Suppose we have a table called "Students" with the following structure:

| StudentID | StudentName      | Course1 | Course2 | Course3    |
|-----------|-----------------|---------|---------|------------|
| 1         | Alice           | Math    | Science | Literature |
| 2         | Bob             | History |         |            |
| 3         | Charlie         |         | Music   |            |
{:class="table table-single"}

In this example, the table violates the principles of 1NF because it contains a repeating group: Course1, Course2 and Course3 are really the same thing stored in three columns. What happens when a student takes a fourth course? And finding everyone who takes Music means checking three columns.

To transform this table into 1NF, we need to remove the repeating groups by creating a separate table for courses. Here's how the transformation can be done:

### Table: Students

| StudentID | StudentName |
|-----------|-------------|
| 1         | Alice       |
| 2         | Bob         |
| 3         | Charlie     |
{:class="table table-single"}

---

### Table: Courses

| StudentID | Course      |
|-----------|-------------|
| 1         | Math        |
| 1         | Science     |
| 1         | Literature  |
| 2         | History     |
| 3         | Music       |
{:class="table table-single"}

---

In the transformed structure, the "Students" table contains unique student information, with each student having a unique identifier (StudentID). The "Courses" table captures the relationship between students and their courses, with each course associated with the respective student.

By separating the repeating group of courses into a separate table, we remove the empty cells and the fixed limit of three courses. Each row now holds one fact: one student takes one course. Finding everyone who takes Music is a simple `WHERE Course = 'Music'`.

This transformation enables easier management, querying, and manipulation of the data. It also allows for efficient handling of course-related information for each student.

By transforming the original table into 1NF, we enhance data organization, eliminate data redundancy, and establish a solid foundation for further normalization, such as Second Normal Form (2NF) and beyond.

## See it in SQLite

Run this complete program to feel the difference. The same question, "who takes Music?", is awkward before the fix and simple after it:

```python
import sqlite3

connection = sqlite3.connect(":memory:")
connection.executescript("""
    CREATE TABLE students_bad (id INTEGER PRIMARY KEY, name TEXT, course1 TEXT, course2 TEXT, course3 TEXT);
    INSERT INTO students_bad VALUES
        (1, 'Alice', 'Math', 'Science', 'Literature'),
        (2, 'Bob', 'History', NULL, NULL),
        (3, 'Charlie', NULL, 'Music', NULL);

    CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT);
    CREATE TABLE courses (student_id INTEGER REFERENCES students(id), course TEXT);
    INSERT INTO students VALUES (1, 'Alice'), (2, 'Bob'), (3, 'Charlie');
    INSERT INTO courses VALUES (1, 'Math'), (1, 'Science'), (1, 'Literature'), (2, 'History'), (3, 'Music');
""")

before = connection.execute(
    "SELECT name FROM students_bad WHERE course1 = ? OR course2 = ? OR course3 = ?",
    ("Music", "Music", "Music"),
).fetchall()
after = connection.execute(
    "SELECT s.name FROM students AS s JOIN courses AS c ON c.student_id = s.id WHERE c.course = ?",
    ("Music",),
).fetchall()
print(before, after)
```

Both print `[('Charlie',)]`, but the first query needs a clause per course column, and a fourth course would mean changing the table itself.

## Try it Yourself

1. Add a fourth course for Alice to each version. Which one needs a change to the table's structure?
2. Write a query that counts the courses each student takes in the fixed version (`GROUP BY`).
3. A `robots` table has columns `sensor1`, `sensor2`, `sensor3`. Redesign it so a robot can have any number of sensors.
4. Challenge: why is storing `'Math, Science'` in a single cell also a 1NF problem?

## Common Issues

- **Problem**: You're tempted to store a list in one cell, such as `'Math, Science'`.
- **Solution**: Make a second table with one row per value.
- **Why**: You can't search, count or join on part of a cell cleanly, and 1NF asks for one value per cell.
